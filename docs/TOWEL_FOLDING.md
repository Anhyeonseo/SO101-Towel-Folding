# 수건 조작 설계

## 목표와 상태

심투리얼 수건 조작은 관측→조작→퇴피/settle→재관측을 반복한다. 상태는 EMPTY, CRUMPLED, PARTIALLY_OPEN, TWO_CORNERS_VISIBLE, ALIGNED, FIRST_FOLD, SECOND_FOLD, COMPLETE/FAILED 및 unknown/가림 정보를 포함한다. 기존 schema의 실제 이름/필드는 관련 config를 따른다.

평면 mask는 보이는 외곽의 증거다. 내부 겹수·들린 높이·숨은 모서리의 정답이 아니다. 들린 수건에 작업대 homography를 적용하지 않는다. fold count는 검증된 동작 context와 관측의 일치로 관리한다.

## 대상 범위

등록된 수건 한 장을 펼치고 정렬한 뒤 직교 방향으로 두 번 접는다. 명목 크기는 300×300 mm, 실제 등록 크기는 304×296 mm이며 물성은 [실측 설정](../config/towel_isaac_s1_material.json)을 따른다. 중간 목표는 평탄 수건의 두 번 접기, 최종 목표는 작업대 안의 구김 상태에서 명목 150×150 mm 형상을 만드는 것이다.

실제 양팔·2.2 mm 패드·상단 카메라 1개·손목 카메라 2개의 형상과 관절 한계를 사용한다. 여러 수건의 얽힘, 매듭, 다른 물체 아래에 낀 수건, 작업대·시야 밖의 초기 상태, 미등록 재질·크기는 초기 범위에서 제외한다.

## 관측 계약

- 고정 Top RGB와 clear pose를 우선 사용한다. 손목 카메라는 접근 crop/가림 해소에 이용하며 정보가 불충분하면 unknown으로 남긴다.
- frame/episode 시각·장치·보정·URDF/계약 version을 확인한다.
- 제어 입력은 실제 영상/관절에서 얻는 값이다. exact particle state와 접촉력은 simulator 진단/평가용이다.
- 손이 수건을 가리면 손을 치우고 settle 후 다시 관측한다. 새 관측 없이 미세 오차를 누적 보정하지 않는다.

## 집기

실물의 눌러 모으기에는 하강 접촉→작업대 지지→제한된 닫힘→낮은 들기→정지 유지가 필요하다. 목표 각도를 순간 적용하는 것과 실제 압착을 구분한다. 의도한 턱 지지 접촉과 카메라 마운트/팔 충돌은 별도 검사한다.

첫 fold의 단일겹과 두 번째 fold의 원래 두 겹을 구분한다. 두 겹을 U자로 모아 꼬집으면 국소 네 겹이 될 수 있으므로 각 원래 겹의 두 가닥과 층간 지지를 확인한다. 입자 4개나 same-particle 양턱 접촉이 네 겹의 증거는 아니다. 원래 재료 영역은 진단에서 고정하고 이동·재접촉을 기록한다. 실제 policy에는 그 ID가 없다.

집기 형성, 들기/정지 유지, 운반, 놓기를 각각 판정한다. 압착 두께/마찰과 전류·부하의 힘 대응이 미검증이면 힘 검증 완료라고 하지 않는다.

## Primitive와 실행

노출 지점 집기, 양손 집기, lift_and_observe, lay_flat, tension_spread, drag/align, micro_drag, lift_pull_place, 다층 fold/release를 제한된 파라미터로 수행한다. 기존 이름과 호출 계약은 config/코드를 따른다. 고속 fling/shake는 저속 primitive의 한계가 확인되기 전 도입하지 않는다.

각 primitive는 pre/postcondition, 관측 유효성, timeout, 거리/속도·관절 제한, slip/충돌 중단, terminal feedback와 재관측을 갖는다. policy가 실패해도 executor의 gate를 우회하지 않는다.

## 두 번 접기

1. 평탄·정렬을 확인하고 한 변의 두 지점을 집는다.
2. 1차 fold를 수행하고 실제 개방/퇴피로 놓는다. 마찰값을 0으로 만들지 않는다.
3. clear 재관측에서 nominal 절반 형상·겹침·말림을 검사한다. 필요하면 최대 2회 bounded correction을 적용한다.
4. 원래 두 겹의 U자 적층과 유지가 검증된 집기로 직교 2차 fold를 수행한다.
5. 양손/단손 전략은 실제 5-DOF 가동범위와 양쪽 손목 카메라 마운트 충돌에 따라 결정한다. 오래된 특정 arm assignment는 필수 조건이 아니다.
6. 손을 열고 치운 뒤 명목 1/4 형상·접힘선·잔류 운동을 확인한다.

S1 아치는 실제 접촉으로 눌리도록 한다. 형상 강제 평탄화나 부착으로 성공을 만들지 않는다. 시뮬레이션에서 저장 S1 형상을 불러오는 국소 시험은 전체 연속 실행과 구분한다.

## 복구와 학습

가림, 겹수 불확실, 미끄러짐, 접힘 오차, tracking fault를 구분한다. 예산은 task contract를 따르며 동일 실패 재호출로 초기화하지 않는다. 학습 출력은 primitive/제한 grasp·placement 파라미터 또는 ACCEPT/RETRY/abstain이다.

R2는 공통 환경/평가와 제한된 baseline, R3/R4는 실제 primitive/평탄 접기, R5는 실물 residual policy와 펼치기를 검증한다. 시뮬레이션은 완벽한 천 복제본이 아니라 task-scale 반응과 실패를 타당하게 재현하는 개발 환경이다. 실제 보정 데이터/오차 범위를 분리하고 동일 held-out/action budget으로 비교한다.

## 최종 품질 기준

실물에서 서로 다른 미사용 초기 구김 30회 중 27회 이상 전체 성공하고 다음을 만족해야 한다.

| 항목 | 기준 |
|---|---|
| 최종 대응 모서리 평균 오차 | 25 mm 이하 |
| 목표 외곽선 IoU | 0.85 이상 |
| 두 접힘선 평균 위치 오차 | 20 mm 이하 |
| 충돌·낙하·작업대 이탈·비명령 동작 | 0회 |
| 실패 처리 | 제한 시간 안에 정지하고 원인 기록 |

실제 정책은 R2와 같은 버전의 관측·행동 계약을 사용한다. 시뮬레이션 학습·계획, 실물 보정, 최종 평가 데이터를 분리하고 같은 데이터 분할·행동 예산의 기준 정책 비교와 시뮬레이션 사용 효과를 보고한다. 순간 마찰 변경·수건 부착·형상 강제 이동·숨은 정답 관측으로 만든 결과는 성공으로 인정하지 않는다.

현재 구현은 [진행 상황](CURRENT_STATUS.md), 중간 단계의 기준은 [로드맵](ROADMAP.md), 시뮬레이션의 물리·집기 판정은 [R2 검증 기준](R2_SIM2REAL_CONTRACT.md)을 따른다.
