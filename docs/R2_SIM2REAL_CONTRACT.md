# R2 검증 기준

## 목적과 현재 판정

실물로 옮길 수 있는 수건 조작을 개발·평가하는 시뮬 기반을 만든다. **현재 R2는 미완료이며 G1 구동/접촉부터 재검증한다.** 현재 결과는 [진행 상황](CURRENT_STATUS.md), 최종 대상과 품질 기준은 [수건 조작 설계](TOWEL_FOLDING.md)를 따른다.

G0–G5는 R2 종료 조건이다. 실행 파일의 S0/S1/second-fold 표기는 개발 경로를 식별하며, 이 검증 단계의 통과 여부와 구분한다.

## 실행 책임

- SceneConfig: 실제 등록 자산·수건·solver/마찰·초기 상태와 입력 해시.
- DrivePolicy: 실물과 대응되는 관절/primitive 명령과 제한. 초기화 외 state 강제 입력을 성공 경로로 사용하지 않는다.
- ContactObserver: solver가 사용한 접촉/힘과 post-step 기하를 구분해 관통·반력·마찰을 기록한다.
- GraspValidator: 집기 형성·하중 유지·미끄러짐·놓기를 단계별 판정한다. 물리를 변경하지 않는다.
- Policy/Executor: 실제 사용 가능한 observation과 bounded primitive만 사용한다. oracle은 분리한다.

이 경계는 필요한 S2 코드부터 적용한다. S1 기준본을 보존하고 S2에 필요한 부분부터 적용한다. 실제 저수준 구동 식별의 최종 값은 R3에서 비교·보정한다.

## G0 — 구성·상태 재현

- 단일 명시적 실행 구성에 자산/코드/관절 계약·관측/행동 버전·solver·seed·초기 상태를 기록한다.
- import 후 전역 설정 변경으로 활성 경로가 불명확해지지 않도록 한다.
- S1 저장 형상+0속도와 전체 연속 실행/solver checkpoint 복원을 구분한다.
- 초기 상태 복원·동일 입력 재실행·종료 원인을 확인한다. 외부 파일 의존과 미보유 파일을 숨기지 않는다.

PASS: 선택한 baseline이 선언한 초기화 방식으로 재현되고 입력 누락/불일치가 거절된다.

## G1 — 실물과 대응되는 구동·접촉

최소 장면은 같은 수건/패드/작업대에서 누르기→닫기→낮은 들기→정지→열기다. 전체 fold 반복보다 먼저 수행한다.

- 그리퍼는 힘/속도 제한 안에서 닫히고 저항에 따른 목표/실제 차이를 표현한다. position command는 가능하지만 매 step 관절 state 덮어쓰기로 접촉을 밀어내면 안 된다.
- 수건 반력의 적용/근사 범위를 명시하고 압착 검증에 필요한 반응을 확인한다. two_way 토글만으로 검증을 대신하지 않는다.
- 입자–턱 접촉과 수건 면 관통, signed distance/법선·반력·추종을 같은 시간축에서 관측한다.
- 고정 패드/이동턱/작업대/카메라 마운트의 의도 접촉과 금지 충돌을 분리한다. 전역 충돌 기준 완화로 통과시키지 않는다.
- 마찰/압착 계수는 측정 범위 또는 미검증 후보로 표시한다. 고무 마찰100이나 수치 contact radius를 실측 집기력/두께라고 부르지 않는다.
- release 중 마찰0 변경, cloth 부착/노드 이동, 순간 형상 평탄화는 성공 경로에서 금지한다.

PASS: 관통을 이용하지 않고 명령 제한/반응/놓기가 일관되며, 같은 시험의 no-contact/미집기 조건을 성공으로 판정하지 않는다. 관통/침투 허용치는 solver와 재료 의미를 구분해 시험 전 고정하고 실패 후 느슨하게 바꾸지 않는다.

## G2 — U자 집기와 관측 계약

- 최초 단일겹과 S1 후 두 겹의 U자 꼬집기를 구분한다. 후자는 각 원래 겹의 되접힌 두 가닥, 턱 사이 국소 네 겹과 층간 지지를 확인한다.
- 접촉 입자 수나 각 겹의 양턱 직접 접촉만으로 적층 압착을 선언하지 않는다.
- 초기 재료 영역을 고정해 형성·들기·정지 유지의 상대 이동을 추적한다. 기준 초기화/접점 교체로 실패를 지우지 않는다.
- 빈 집기·한 겹 누락·미끄러짐을 포함한 음성 사례를 거절한다. 진단의 단면 정답과 실물 제어기의 겹수 확신을 혼동하지 않는다.
- 제어 observation은 상단/손목 영상 기반 상태·가림/unknown·관절 피드백과 실제 제공 가능한 신호다. 원래 재료 ID/완전한3D/정확한 힘은 평가/teacher 전용이다.
- force 센서가 없는 실물에 정확한 힘 입력을 요구하지 않는다. raw 전류/부하를 사용할 경우 보정과 지연/유효 범위를 명시한다.

PASS: 형성→낮은 들기→정지 유지가 구분돼 검증되고, oracle을 제거한 executor도 같은 observation/action 구조로 실행 가능하다.

## G3 — 연속 두 번 접기 baseline

평탄 등록 수건에서 집기→1차 접기→놓기/퇴피→관측→다층 집기→2차 접기→놓기/퇴피를 연결한다. 중간 S1 형상 강제 교체 없이 연속 실행한다. 보정이 필요하면 실제 관측 가능한 상태와 정해진 예산으로 수행한다.

- 단팔/양팔 전략은 actual mount·관절·작업대와 오차 범위 검사로 선택한다. 이전의 고정 arm assignment를 새 집기에 무조건 복사하지 않는다.
- 각 단계는 실제 유지, 충돌, 최종 mask/접힘선·겹침·잔류 운동을 검사한다.
- baseline 비교 최소3회 연속 명목 실행을 사전에 정한 입력으로 수행하고 전부 기록한다. 이는 높은 실물 성공률의 통계 증거가 아니다.

PASS: 3회 모두 조작·형상 기준 통과, 금지 충돌/관통 악용/낙하0회. 성공 seed만 골라 baseline으로 승격하지 않는다. 실물 전이 품질 인증은 R4에 남는다.

## G4 — 오차·실패 분포

튜닝에 쓰지 않은 고정 조건 최소20개에서 초기 배치/접힘·등록 오차·마찰/두께 후보·닫힘/추종·영상 가림/지연을 검사한다. 실제 측정 범위와 미확정 가정은 구분하고 무차별 조합 탐색을 하지 않는다.

PASS: 조건별 성공률과 실패 signature, 안전 거절, 소요 시간/재시도 수가 모두 보고되고 금지된 성공 판정0회. 이 단계의 성공률 임계값은 결과를 본 뒤 정하지 않는다. 일반화 주장은 사전에 정한 범위에서만 한다. 모든 조건을 성공시키는 것보다 실패와 unknown을 올바르게 처리하는 기반을 요구한다.

## G5 — 학습 환경·실물 인계

- reset/observation/action/reward/termination 버전과 dataset split을 고정한다.
- action은 승인 예정의 bounded primitive/파라미터다. oracle 정보 누출·무한 재시도·물리 오류를 통한 reward 획득을 검사한다.
- heuristic baseline과 제한된 학습/rollout smoke 검증을 제공한다. R2에서 대규모 학습이나 실제 heuristic 성능 초과까지 요구하지 않는다.
- R3에 동일 명령·카메라 상태·관절/부하 기록, 실제 비교 항목과 미검증 계수 목록을 넘긴다.

PASS: 제한된 환경 실행/정책 평가 경계가 작동하고 실제 bridge/관측으로 교체할 인터페이스가 명확하다. simulator privileged 정보는 실물 policy 입력에 없다.

## 비용과 중단 규칙

한 시험은 원인 가설 하나를 검증한다. 시작 오류/충돌 여유 문제/접촉 실패/미끄러짐을 구분한다. 변경 후 관련 최소 시험만 먼저 실행한다. 같은 실패가 새 관측 없이 반복되면 중단하고, 원인 가설이나 물리 모델의 변경 근거를 검토한다. S1 물성·패드·solver는 잠금 유지하며 변경 실험이 필요하면 별도 범위로 명시한다.
